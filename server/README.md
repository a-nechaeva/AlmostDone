# AlmostDone REST API

Контракт API: [OpenAPI 3.1](../docs/api/openapi.yaml).

Базовый путь — `/api/v1`. Контракт описывает авторизацию, профиль, продукты пользователя, избранное, каталог, рекомендации и распознавание.

Для защищённых методов используется `Authorization: Bearer <access_token>`. Заголовки `If-Match` и `Idempotency-Key` передаются для операций, где они указаны в контракте.

## Запуск

Нужен Python 3.12 или новее. Пример для Windows PowerShell из корня репозитория:

```powershell
python -m venv server/.venv
.\server\.venv\Scripts\python.exe -m pip install -e ./engine -e "./server[postgres]"
.\server\.venv\Scripts\python.exe -m uvicorn almostdone_server.main:create_app --factory --host 127.0.0.1 --port 8000
```

Без `ALMOSTDONE_DATABASE_URL` сервер использует данные в памяти и демонстрационный каталог. Для подключения к существующей PostgreSQL задайте эту переменную окружения перед запуском. Остальные параметры перечислены в [.env.example](.env.example).

После запуска:

- Swagger UI: <http://127.0.0.1:8000/docs>.
- OpenAPI JSON: <http://127.0.0.1:8000/openapi.json>.
- Проверка процесса: <http://127.0.0.1:8000/api/v1/health>.

## Неполные данные каталога

Необязательные ингредиенты с неизвестным количеством остаются в ответе API (`optional=true`, `required=null`). В расчётную модель движка передаётся только обязательный состав: необязательные ингредиенты и так не участвуют в его метриках. Сведения об их аллергенах сохраняются в API; исключённый аллерген необязательного ингредиента даёт предупреждение `skip_optional`.

Рецепт, который нельзя рассчитать без подстановки отсутствующих данных, доступен по ID и в подборе `mode=all`. Его неподтверждённые оценки возвращаются как `null`, доступность — `unknown`; такой рецепт не подтверждает фильтр по неизвестной метрике и не включается в `now` / `buy_1_3`. Полностью заполненные рецепты продолжают рассчитываться движком независимо от неполных соседних записей. Если движок не поддерживает запрошенное число порций, сервер сохраняет карточку с этим `servings`, но не выдаёт исходные количества за пересчитанные.

Нерассчитанные рецепты остаются в пагинации и перечисляются в `graph.unrepresented_recipe_ids`; подтверждённые покупки для них не создаются. Сведения о неполноте аллергенов передаются через `allergens.completeness` и предупреждения пригодности. Сервер не изменяет исходный каталог и не подставляет фиктивные цены, количества или КБЖУ.
